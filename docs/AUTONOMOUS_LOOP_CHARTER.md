# PigOS 자율 루프 헌장 (퇴근 후 무인 실행)

> 목적: 사람이 없는 몇 시간 동안 **버그헌팅 + 테스트 커버리지 확장 + 회귀 워치독**을 순환하며
> PigOS를 단단하게 만든다. 결과는 아침에 diff 리뷰. **안 깨지게**가 최우선.

## 절대 가드레일 (위반 금지)
1. **git push 금지.** 로컬 커밋만. (CLAUDE.md 규칙)
2. **운영/AWS/외부 유료 API/env 비밀값 변경 금지.** 로컬 dev 스택만.
3. **커밋은 반드시 GREEN 게이트 통과 후에만**: `tsc --noEmit` 0 + 관련 테스트 통과. 깨진 채 커밋 금지.
4. **한 라운드 = 한 가지 작게.** 대형 리팩터/전면 재작성 금지. 되돌리기 쉬운 단위로.
5. high-stakes(KPI계산·룰엔진·farm_id 테넌트격리·권한·과금·인증·Alembic·sync충돌) 수정 시 **verify 스킬** 사용.
6. 디자인 토큰 규칙 유지: raw hex/블루-퍼플 금지(Forest Green 토큰). i18n 5개어 동시 갱신.
7. 불확실하면 **수정 대신 리포트**에 기록하고 다음으로. 멈추지 말 것.

## 매 라운드 절차 (순서대로)
1. **워치독**: Docker(postgres/redis)·API(:8000/health)·web(:3000) 살아있는지 확인. 죽었으면 복구
   (Docker Desktop 재기동 → `docker compose up -d postgres redis` → alembic head → uvicorn → next start).
   e2e 농장(`932208a6-…`) 누적 sow soft-delete 정리.
2. **회귀 베이스라인**: `cd api && uv run pytest tests/ -q` + `cd src && npx playwright test --config=playwright.live.config.ts`.
   실패 있으면 **그 라운드는 회귀 수정에 전념**(새 작업 금지) → 근본원인 수정 + 회귀테스트 → 커밋.
3. 베이스라인 green이면 아래에서 작업 선택. **(0) 기능 작동 검증이 최우선** — 사용자 강조:
   "가장 중요한 게 기능 작동". 매 라운드 (0)을 먼저 1건 하고, 여유 시 라운드#%3으로 (1)~(3) 중 하나 추가.
   - **(0) 기능 작동 E2E 검증(최우선)**: 실제 사용자 플로우가 화면에서 끝까지 동작하는지 검증.
     로그인→대시보드→모돈등록→교배→분만→이유→이유두수/상태 반영, 도폐사, 비육그룹, 알림→AI상세,
     리포트(생산/번식/분만/비육/종합일보) 렌더+숫자, 언어전환, 권한(VIEWER 읽기전용). 깨진 기능 발견 시
     **그 라운드는 수정에 전념** → 재현 live E2E → 근본수정 → 통과 → 커밋. (가짜 통과 금지)
   - **(1) 버그헌팅**: high-stakes 적대적 점검(KPI 경계값, 검증기 우회, 테넌트 누수, 상태전이 빈틈,
     리포트 집계 오차, 날짜 엣지). 발견 시 재현테스트 → 수정 → 재검증 → 커밋.
   - **(2) 관리자 페이지 빌드(/admin, 신규 — 사용자 요청)**: SUPER_ADMIN 전용 게이트.
     **MVP 범위(읽기 위주, 기존 엔드포인트만 사용 — 새 백엔드 최소화)**:
     ① 조직/농장 트리(org/{id}/tree, org/{id}/farms) ② 농장 멤버 목록(farms/{id}/members)
     ③ 시스템 개요(농장 수·모돈 수·활성 신호 카운트) ④ 멤버 역할 표시.
     라우트는 비관리자 접근 시 차단(리다이렉트/403 UI). i18n 6개어. 한 라운드 = 한 섹션씩 작게, tsc+빌드+
     read 스윕 추가 → 커밋. CRUD(역할변경 등)는 백엔드 엔드포인트 있을 때만, 없으면 리포트에 "백엔드 필요" 기록.
   - **(3) 하드닝/테스트추가**: 미커버 플로우 테스트(이벤트 수정/삭제 UI, 리포트 CSV, 페이지네이션,
     부분이유 반복, 양자 거울) 또는 저위험 개선(i18n 누락, 빈상태/로딩, 토큰 위반 잔재, null 안전).
4. **로그**: 매 라운드 `docs/verification/autonomous_loop_2026-06-22.md`에 1줄+근거 추가
   (라운드#, 한 일, 결과, 커밋해시 또는 "리포트만"). 위조 금지 — 실패는 실패로 기록.
5. 다음 라운드로. 컨텍스트가 너무 커지면 로그에 현재상태 요약 남기고 계속.

## 우선 작업 백로그 (버그헌팅·테스트 후보)
- 이벤트 수정/삭제 UI(P12-1) live E2E — PATCH/DELETE + 상태 롤백을 화면에서 왕복
- 리포트 CSV 내보내기 정확성(/reports exportCsv) + 종합일보/생산성적 빈농장·대량 200
- 페이지네이션(boars/finishers/record 모돈리스트) 경계
- KPI 경계값: PSY/NPD/분만율 tier 임계 정확성(status.ts) + 백엔드 계산 일치
- 테넌트 격리: 다른 farm_id 리소스 접근 403/404 (alerts/reports/events/sows)
- 부분이유 여러 번 → 잔여 0 시 409, 상태 LACTATING 유지/OPEN 전이
- 양자 거울레코드: 한쪽만 전송 시 양쪽 정합, self-target 차단
- 한국어 게이트: 비관리자 ko 차단 회귀(이미 1개 있음 — 확장)
- i18n: en 기준 5개어 키 패리티 자동 점검(누락 0)
