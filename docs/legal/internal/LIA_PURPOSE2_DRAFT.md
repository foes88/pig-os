## 1. 1단계 — 목적 테스트 (Purpose Test): 이익이 정당한가

**회사의 이익**:
1. 익명·집계 산업 통계 상품(PigSignal)의 개발·판매 — 상업적 이익. 상업적 이익도 LI가 될 수 있음(GDPR Recital 47, ICO 지침 — `CONFIRMED_LAW`/`OFFICIAL_GUIDANCE`).
2. 무료 Core 서비스의 지속 가능성 재원 확보 — 통계 수익이 무료 제공 구조를 지탱.

**제3자·공익적 이익**:
3. 양돈 산업 전반의 생산성 벤치마크·질병 동향 등 산업 데이터 인프라 제공 — 개별 농가(자기 성적의 산업 내 위치 파악), 산업 단체·연구기관, 방역 정책에 간접 기여.

**적법성**: 익명 통계의 유상 제공은 3개 관할 모두 그 자체로 금지되지 않음(단, TH는 LI 선례 미확립 — §4.3). 이익은 현실적·구체적이며 가정적이지 않음(실제 상품 계획 존재).

**판정(제안)**: PASS — `INTERNAL_POLICY_PROPOSAL`. 상업적 이익 중심임을 감추지 않고 고지문에 "유상 제공 포함"을 명시하는 것이 투명성 요건과 정합(CONSENT_SPEC §3.2 문구).

## 2. 2단계 — 필요성 테스트 (Necessity Test): 이 처리가 꼭 필요한가

**질문**: 목적(산업 통계 상품)을 덜 침익적인 방법으로 달성할 수 있는가?

**필요성 테스트의 중심은 "같은 목적을 동등하게 달성할 수 있는 덜 침해적인 처리 설계가 있는가"이다** (EDPB — 동일하게 효과적인 덜 제한적 방법이 있으면 LI 불가). 처리 설계 대안 평가:

| 처리 설계 대안 | 평가 |
|---|---|
| 식별 상태로 제공 | 더 침익적 — 배제. 본 설계는 정반대(비가역 익명화 후에만 산출) |
| 공개 통계만 사용 | 공공 축산 통계는 농장 수준 생산성적 미포함 — 목적 달성 불가 |
| 덜 침해적 설계 요소의 채택 여부 | **데이터 최소화**(집계값만 출력·레코드 수준 금지·자유 텍스트 전면 제외), **즉시 익명화**(통계 산출 직전 파이프라인에서 익명화, 개인 데이터 외부 미반출), **세분도 축소**(준식별자 구간화·소수 셀 억제), **처리 빈도 감소**(배치 단위 산출) — 모두 채택됨(ANONYM_STANDARD §2) |
| **채택 설계** | 원데이터는 서비스 운영(목적①) 범위에 머물고, 통계 산출 직전 익명화 — 목적 달성이 가능한 설계 중 **가장 덜 침해적인 구조** |

**판정(제안)**: 조건부 PASS — 덜 침해적 설계 요소(최소화·즉시 익명화·세분도 축소·빈도 감소)를 모두 채택한 상태에서, 목적을 동등하게 달성하는 더 덜 침해적인 설계가 확인되지 않음. `INTERNAL_POLICY_PROPOSAL`

## 2B. 법적 근거 선택에 관한 별도 검토 (동의 vs LI — 필요성 테스트 밖)

동의와 정당한 이익은 서로 다른 적법근거이며, **동의 관리의 운영 부담만으로 LI의 필요성이 입증되지는 않는다.** 옵트인 방식은 철회 전 처리의 적법성을 소급하여 무효화하지 않는다(GDPR Art. 7(3)). 동의 모델의 실무 고려사항 — (i) 참여율·표본 편향으로 인한 통계 대표성 저하 가능성, (ii) 배치별 입력 제외·기생성 산출물 관리, (iii) 동의 증빙 관리 — 은 **법적 근거 선택과 형량 판단의 참고자료**로 사용한다. **파일럿 또는 예상 참여율 분석으로 동의형 표본이 동일한 통계 목적을 동등하게 달성할 수 없는지 확인한다 [OPEN — 파일럿/참여율 분석 결과 기입].** 이 분석 결과에 따라 근거 선택([D-01])의 타당성을 재평가한다.

## 2A. Article 6(4) 목적 호환성 테스트 (Compatibility Assessment)

> **신설 (v0.2)**: 목적①(서비스 운영)로 수집한 개인정보를 목적②(산업 통계 상품)로 **추가 처리**하는 구조이므로, LIA와 **별도로** GDPR Art. 6(4)의 목적 호환성을 평가한다(EDPB Guidelines 1/2024 v1.0 — public consultation version, `DRAFT_GUIDANCE`). LIA PASS와 6(4) PASS는 별도 판정한다.

| Art. 6(4) 평가 요소 | 평가 |
|---|---|
| (a) 원목적과 추가 목적 간 연관성 | 서비스 운영(생산 관리)과 산업 통계 생성은 동일 데이터의 연장선상 활용이나, **상업적 재판매**라는 목적 성격 차이 존재 — 중립~부정 요소 |
| (b) 수집 맥락·정보주체와의 관계 | B2B 생산관리 도구 가입 맥락. 농장주가 자기 경영 목적으로 입력한 데이터 — 통계 상품화는 수집 맥락의 자연 연장으로 단정 불가, 고지(STEP 2)로 보강 |
| (c) 데이터 성격 | 특수범주 아님(민감정보 유입 차단 설계). 단 개인사업자의 경영·재무 성격 데이터로 민감도 중간 |
| (d) 정보주체에 미치는 결과 | 익명·집계 후 제공으로 개인 수준 결과 차단 설계. 잔여 위험: 재식별 시 사료회사·금융기관·보험사 등 **구매자의 보조정보 결합**에 의한 경제적·평판상 영향(거래조건·신용평가 활용 가능성) |
| (e) 안전장치 존재 | 익명화 파이프라인·릴리스 게이트·이의권·구매자 계약 통제(§3.2) — 긍정 요소. Art. 89(1) 안전조치 원용은 PigSignal이 통계·연구 특례에 자동 해당하는 것으로 전제하지 않으며 `COUNSEL_CONFIRMATION_REQUIRED` |

**판정: `OPEN`** — 다음 매트릭스를 확정한 후 호환성을 판정한다. **변호사 확인 전 PASS로 인용하지 않는다.**
- [OPEN] 목적① 데이터의 **최초 적법근거** (계약 이행 범위 확정)
- [OPEN] **가입 코호트 구분**: 직접 PigOS 가입자 vs 기존 피그플랜 이관자 — 각각의 가입 시점·고지문 버전(notice_version)
- [OPEN] **수집 경로**: 기업고객 경유 데이터 여부 (해당 시 §0 적용 범위 제외 — 본 평가 대상 아님)
- [OPEN] 국가·데이터 항목별 수집 맥락
특히 기존 피그플랜 이관 회원은 신규 회원과 합리적 기대가 다르므로(§3.1 코호트 분리), 이 매트릭스 없이 호환성 PASS를 내릴 수 없다.

## 3. 3단계 — 형량 테스트 (Balancing Test): 정보주체 권리가 우선하지 않는가

### 3.1 정보주체에 미치는 영향

| 영향 요소 | 평가 |
|---|---|
| 프라이버시 침해 정도 | 낮음(설계상) — 산출물은 비가역 익명·집계 상태. 개인·농장 식별 정보는 외부 미제공 |
| 재식별 위험 | **핵심 잔여 위험.** 지역×규모 희소 셀, 구매자 보조정보 결합(인테그레이터·사료회사), 차분 공격 — ANONYM_STANDARD §3.1 motivated intruder 3시나리오로 평가 |
| 합리적 기대(reasonable expectation) | STEP 2 고지("익명 통계 활용 + 유상 제공" 명시)는 합리적 기대 평가의 **긍정적 요소이나, 고지 자체만으로 합리적 기대가 확정되지는 않는다**(EDPB — 처리방침 제공 사실만으로 기대 형성 불인정). 관계의 성격, 수집 장소·상황, 서비스 특성, 계약 내용, 과거 데이터 활용 관행, 실제 UI 노출을 함께 평가한다. **코호트 분리 평가**: (i) 신규 PigOS 회원 — STEP 2 고지 경유, 기대 형성 상대적 양호 / (ii) **기존 피그플랜 이관 회원 — 가입 시점 고지 상태·과거 관행이 다르므로 별도 코호트로 평가.** F5(게시본·운영 불일치) 해소 + V1 실사 전 기대 형성 판단 보류 — `COUNSEL_CONFIRMATION_REQUIRED` |
| 취약 정보주체 | 해당성 낮음(사업자 대상 B2B 서비스). 개인사업자 농장주의 소비자 유사 지위는 별도 논점(GB_EU Q8) |
| 민감정보 유입 | 차단 설계 — 사람 건강·생체정보 입력 필드 분리·차단(BR Art. 11 LI 불가 대응, ADDENDUM_BR 제4조2·TH 제9조2) |

### 3.2 안전장치 (형량을 회사 측으로 기울이는 요소)

1. **7단계 익명화 파이프라인** — 직접 식별자 삭제, 준식별자 구간화, 소수 셀 억제(k), 지배율 통제, 이상치 제외, 차분 공격 통제 (ANONYM_STANDARD §2). **단, 코호트 k 및 지배율 기준은 익명성을 단독으로 입증하는 기준이 아니라 위험통제 파라미터다.** 각 릴리스는 EDPB 3대 기준 — **No Record Isolation(개별 레코드 분리 불가) · No Linkage(연결 불가) · No Inference(추론 불가)** — 평가와, 구매자의 보조정보를 포함한 **contextual assessment**를 별도로 통과해야 한다(EDPB 02/2026: 집계 데이터도 외부 정보 결합 시 특정 개인에 관한 의미 있는 추론 가능). RRA(ANONYM_STANDARD §3)의 판정 항목을 이 3대 기준에 명시적으로 매핑하고, **익명성은 관련 주체별 관점에서 판단한다(EDPB 02/2026)**: ① **와이즈레이크 내부 관점**(원본·매핑정보·농장 데이터 접근 가능 — 구매자에게 익명이어도 회사에는 개인정보일 수 있음), ② **계약 구매자 관점**(보조정보 결합 시나리오), ③ **합리적으로 접근 가능한 외부 제3자 관점**. RRA에 이 3개 관점 판정란을 추가한다.
2. **릴리스 게이트 + 원장** — RRA 사전 평가, DATA_RELEASE_LEDGER 기록, 게이트 미통과 릴리스 금지 (§3·§4)
3. **구매자 계약 통제** — 재식별 금지·결합 금지·재판매 제한·감사권 (§5). **계약상 재식별 금지는 기술적 익명화를 보완할 수 있을 뿐, 기술적 조치를 대신할 수 없다**(EDPB) — 계약 통제 단독으로 익명성을 주장하지 않는다.
4. **이의권(옵트아웃) 실효 보장** — Art. 21 이의/제외요청 채널 상시 제공, 접수 시 다음 배치부터 입력 단계 제외(CONSENT_SPEC §6 — 산출물 후처리가 아닌 입력 제외)
5. **투명성** — 고지문에 유상 제공 명시, 이의 채널 안내, 프라이버시 노티스 기재
6. **지속 재평가** — 반기 재평가 + EDPB 02/2026 최종본 채택 시 재검토 트리거 (§6)

### 3.3 형량 판정

정보주체에 대한 잔여 위험(재식별)은 §3.2의 기술·계약·절차 통제로 "합리적으로 낮은(remote)" 수준으로 관리되도록 **설계되었으나, D-05 실데이터 검증 전에는 입증되지 않았다**(ICO 기준). 이의권으로 개별 통제권이 보장된다. 이익(§1)과 비교할 때 정보주체의 이익·권리가 명백히 우선한다고 보기 어렵다.

**판정(제안)**: **조건부 PASS** — `INTERNAL_POLICY_PROPOSAL`. 조건:
- (i) 릴리스 게이트 수치 확정 [D-05] 및 실데이터 검증 — **수치 미확정 상태에서는 형량의 전제(재식별 위험 통제)가 미완**
- (ii) F5(KR 게시본·운영 불일치) 해소 + V1(동의 UI·로그 실사) — 합리적 기대 형성의 사실관계 확정
