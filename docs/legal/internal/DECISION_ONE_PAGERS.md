## D-05 — 릴리스 게이트 수치 (최소 코호트 k · 지배율)

**질문**: PigSignal 산출물 릴리스 시 최소 코호트·지배율 기준을 어느 수치로 확정하나?

| 옵션 | 내용 | 비고 |
|---|---|---|
| (a) 후보값 그대로 확정 | 기본 k=10 / 세분 상품 k=20 + 단일 70%·상위2 85% | 통계 검증 없이 확정 — 빠르나 근거 약함 |
| (b) 실데이터 검증 후 확정 (권고) | 실제 셀 분포 분석 → 수치 조정 → 변호사+통계 확인 | ANONYM_STANDARD §8-1 절차 그대로 |
| (c) PigCHAMP식 완화 | 최소 3농장·단일 60% (경쟁사 공개 수치) | 상업 판매+구매자 보조정보 시나리오엔 취약 |

**추천**: **(b)**. 파이프라인·평가·원장·계약(§2~§5)은 수치와 무관하게 **지금 즉시 시행**하고, 수치만 실데이터 분석 후 확정. 파일럿 기간은 후보값(k=10/20)을 가이드로 운영.
**결정을 미룰 때의 비용**: PigSignal 정식 판매 차단 상태 지속(OPEN_QUESTIONS §F — 유일한 "글로벌 게시 차단" 항목).
**필요한 입력**: 실데이터 셀 분포 리포트(데이터팀), 변호사 의견(Q4·코호트 충분성).

## D-06 — KR 코호트 5: 이원 유지 vs 전사 상향

**질문**: 현행 피그플랜 KR k=5를 유지(이원 기준)하나, 글로벌 수치로 통일 상향하나?

| 옵션 | 장점 | 단점 |
|---|---|---|
| (a) 전사 통일 상향 (k=10/20) | 단일 방어 논리("전 세계 최고 기준"), 운영 실수 리스크 제거 | KR 기존 상품 세분화 후퇴, 소지역 셀 탈락 증가 |
| (b) KR 5 유지 + 글로벌 10/20 (이원) | KR 상품 커버리지 유지 | "왜 한국 농가만 보호가 낮나" 공격 표면 — 재동의 사태 재연 트리거 가능. 등가 보호 입증 부담 |

**추천**: 사업 영향(커버리지 감소 폭)을 실데이터로 확인하기 전엔 결정 보류가 합리적이나, **방향성은 (a) 통일 상향이 방어에 유리**. D-05와 같은 실데이터 분석에서 함께 결론 내는 것이 효율적.
**필요한 입력**: KR 산출물의 k=10 적용 시 셀 탈락률(데이터팀).

## D-07 — 중국 진입 구조 (현재 HOLD)

**질문**: 중국 시장을 어떤 구조로 들어가나, 혹은 계속 막아두나?

| 옵션 | 내용 |
|---|---|
| (a) 직접 진출 | 국외이전 별도동의·SCC 신고·데이터 현지화 등 최중량 규제 직접 부담 |
| (b) 현지 법인 | 비용 최대, 규제 리스크는 낮아짐 |
| (c) 파트너 라이선스 | 데이터를 국경 밖으로 안 가져오는 구조 — 부담 최소 |
| (d) HOLD 유지 (현행) | 서비스·수집 차단 지속 |

**추천**: **(d) HOLD 유지**. 리서치 결론이 "부속조항으로 해소 불가"(CN_legal §8)이고, 진입하더라도 (c) 파트너 구조 + "CN 데이터 PigSignal 편입 금지 + 질병 데이터 제외"를 기본 채택. **중국 매출 기회가 구체화되기 전까지 재론 실익 없음** — 이 건은 "결정"이 아니라 "재론 트리거 정의"(예: 중국 파트너 제안 수신 시)만 해두면 됨.
**필요한 입력**: 사업 측 중국 우선순위 판단만. 법무 입력 불요(진입 결정 시 현지 법무 필수).

## D-08 — 베트남 출시 게이트 해제

**질문**: VN 유료·마케팅 보류를 언제 푸나?

**해제 조건 (모두 충족 필요)**: ① TIA/DPIA 제출 실무 확인(역외 사업자 절차·베트남어 서류) ② 데이터 서비스 라이선스(Decree 169/2025) 해당성 확인 ③ 현지화 의무(Decree 53/2022) 해석 확인.
**추천**: **게이트 유지 + 변호사 회신(Q5·Q7) 수신 즉시 재평가**. 무료 Core 제공은 게이트 안에서도 가능(현행 설계). PigSignal 상품화는 ② 확인 전 금지 유지.
**결정 성격**: 지금 "해제"를 결정하는 게 아니라, **회신 후 해제 판단을 위한 조건표가 이미 있으니 추가 결정 불요** — 회신 도착이 트리거.
**필요한 입력**: LAWYER_BRIEF VN 질의 회신.

## D-09 — 태국 출시 게이트 해제

**질문**: TH 유료·본격 마케팅 보류를 언제 푸나?

**해제 조건**: ① 현지 대리인 지정(§37(5)) — **해법 확정됨(상용 대행 서비스), 계약만 남음** ② §29 이전수단(SCC 계열) 확정·체결 ③ 대리인 면제 고시 존부 확인(Q9).
**추천**: **"착수"와 "체결"을 분리한다.** 대행업체 조사·견적·계약서 검토 **착수는 지금 승인** 가능(회신 불요, 비용 소액). 단 **최종 서명(체결)은 Q9 면제 고시 존부 확인 후** — 면제 대상으로 확인되면 계약 자체가 불필요해질 수 있으므로. ②는 회신 대기.
**필요한 입력**: 대행업체 견적·계약서 검토(운영 — 착수), LAWYER_BRIEF TH Q6·Q9 회신(체결 조건).

## D-13 — controller/processor 역할 확정 ⚠ B2B 출시 P0

**질문**: 처리 유형별 역할(컨트롤러/프로세서)을 어떻게 확정하나?

**제안돼 있는 매핑** (NOTICE 제7조·DPA 제1조·ADDENDA v1.4 참조 조항):
가입·결제·보안 = 와이즈레이크 controller / 기업고객이 입력한 직원·계약농가 데이터 = 고객 controller·와이즈레이크 processor / **PigSignal = 원칙적으로 와이즈레이크 독립(independent) controller.** 공동(joint) controller 표시는 고객과 와이즈레이크가 동일 처리의 **목적과 핵심 수단을 실제로 공동 결정**하는 경우에만 사용한다 — 고객이 데이터 사용을 허용했다는 사실만으로 공동 controller가 성립하지 않으며, 역할은 계약 명칭이 아니라 사실관계로 판단된다(EDPB 확정 가이드라인).

**핵심 쟁점 (CROSS_DOC 경고 + EDPB 법리)**: processor가 고객 지시를 넘어 **자기 목적을 정해 처리하면 그 처리에 대해 controller로 취급되어 제재 대상**이 될 수 있다. 따라서 기업고객이 맡긴 직원·계약농가 데이터를 와이즈레이크가 자체 PigSignal 상품에 넣는 것은 "processor의 부가 활용"으로 처리할 수 없다 — **B2B 출시 P0 블로커.**

**권장 확정문** (대표 승인 시 이 문구로 잠금):
1. 기업고객이 제공하거나 통제하는 직원·계약농가·농장 데이터는 **기본적으로 PigSignal 및 AI 학습 목적에서 제외**한다.
2. 해당 데이터에는 시스템상 **`purpose_2_eligible=false`를 기본 적용**하고, **tenant·source 단위로 기술적으로 분리**한다.
3. 예외 사용은 (a) 별도 법무 승인, (b) 고객의 적법한 지시 또는 별도 수집 구조, (c) 정보주체 고지, (d) 역할 재설계, (e) 익명성 릴리스 게이트 통과가 **모두** 확인된 경우에만 허용한다.
4. **와이즈레이크는 목적②를 위해 개인정보를 선별·익명화·집계하는 처리 단계에서 원칙적으로 독립 controller로 검토한다.** 릴리스된 산출물은 와이즈레이크·구매자·기타 관련 주체 각각의 관점에서 익명성이 입증된 범위에 한하여 개인정보 보호법령 적용 밖의 익명정보로 취급한다. 공동 controller 표시는 실제 공동 목적·수단 결정이 확인된 경우에만 사용한다. (근거: EDPB Guidelines 07/2020 — 최종본)

**향후 예외 구조(참고 — 이번 출시 제외)**: 기업고객 데이터를 꼭 활용하려면 "고객(controller)이 익명화를 명시적으로 지시 → 와이즈레이크는 익명화 완료까지 processor → 릴리스 평가 통과 → 익명 산출물 후속 사용권을 계약으로 확보" 구조를 검토할 수 있다. 단 익명화 완료 전부터 와이즈레이크가 자기 PigSignal 목적을 독자 결정하면 다시 controller 문제가 발생한다.

**필요한 입력**: 대표의 확정문 승인 → DPA·NOTICE·CONSENT_SPEC 반영 + LAWYER_BRIEF 회신으로 최종 확정.

## D-15 — 유료/무료 기능 경계

**질문**: 무료 Core와 유료 AI의 실제 경계(조기경보 무료 여부 등)를 어디로 확정하나?

**현황**: 약관 문구는 "화면·가격표 표시 기준"으로 완화 반영 완료 — **약관은 더 이상 이 결정을 기다리지 않음**. 남은 것은 순수 사업 결정 + 가격표 문서.
**추천**: 약관 트랙과 분리해 **프라이싱 결정으로 이관**. 결정 시 반영처는 가격표·유료 서비스 정책(미작성 — B섹션 크레딧·환불과 함께 일괄 작성이 효율적).
**필요한 입력**: 사업 판단만.
