## 이 세션에서 한 일

### 1. Rule Engine 구축 (`api/app/engine/`)

핵심 설계 원칙: **LLM은 판단 금지 — Rule Engine이 판단, Renderer가 표현**

| 파일 | 역할 |
|------|------|
| `engine/rule_engine.py` | RuleContext, Finding, StructuredResult, Rule, RuleRegistry, RuleEngine |
| `engine/rules/base.py` | Base 규칙 4개 (NPD/PSY/Farrowing/Inventory) 자기등록 |
| `engine/renderer.py` | Template Renderer (en/ko) — Addon #1에서 LLM Renderer로 교체 가능 |
| `engine/__init__.py` | 퍼블릭 API export |
| `engine/rules/__init__.py` | base rules import → RuleRegistry 자동 등록 트리거 |

#### Rule Engine 아키텍처
```
RuleContext (KPI 스냅샷 + 농장 메타)
    → RuleRegistry.for_intent(intent, tiers)
    → Rule.fn(ctx) × N → Finding[]
    → StructuredResult { severity, findings, as_of }
    → renderer.render_text(result, locale)
    → ChatResponse
```

#### Tier 필터링
- `tiers=["base"]` → 항상 활성
- `tiers=["base", "fcr"]` → FCR Addon 구독 시 추가 규칙 활성화
- dashboard intent → 모든 등록 규칙 실행 (tier 필터 적용)

#### 등록된 Base 규칙
| rule_id | domain | 트리거 조건 |
|---------|--------|-----------|
| `npd.overdue` | npd | NPD > target |
| `psy.below_target` | psy | PSY < target (cross-KPI: NPD 높으면 원인 포함) |
| `psy.no_data` | psy | PSY 데이터 없음 (INFO) |
| `farrowing.low_rate` | farrowing | 분만율 < 국가별 target |
| `inventory.zero` | inventory | 활성 모돈 0두 |
