# PigOS 개발 참고 — 모돈 데이터 정합성 & Validation (PigPlan 교훈)

> 레거시 PigPlan에서 데이터가 꼬이는 지점과 검증해야 할 도메인 불변식 정리.
> PigOS는 멀티국가·멀티테넌트 신규 시스템이므로 **레거시 구조 복제가 아니라 "꼬임의 원인"을 알고 네이티브로 방어**하는 게 목적.
> 근거: 모돈 작업기록 구조(복구 작업 검증) + `handoff/pigplan-rules/`(KR 룰셋 VALID_RANGES·DATA_QUALITY_GUARD·KPI_DRIVER_MAP 등).

---

## 1. 모돈 식별 — 키 vs 이름 (꼬임 1순위 원인)

데이터가 모돈별로 꼬이는 가장 흔한 원인은 **"이름으로 데이터를 연결"** 하는 것.

| 구분 | 성격 | PigPlan | 규칙 |
|---|---|---|---|
| **내부키 (PK)** | 시스템 증가값 시퀀스 | `PIG_NO` (FARM_NO 내 시퀀스, 예 7194) | **모든 FK·조인·이력은 이 키로.** 사용자 노출/입력 대상 아님. 불변. |
| **이름 (표시번호)** | 사람이 붙인 이름 | `FARM_PIG_NO` (예 `24-261`) | 표시·검색용. **변경 가능·중복/재사용 가능.** 절대 조인/FK 키로 쓰지 말 것. |

**원칙 (PigOS):**
- 모돈 = `(farm_id, sow_internal_id)` 로 식별. `sow_internal_id` = 시스템 생성 불변 키(UUID 또는 farm 내 시퀀스).
- 표시번호(이름)는 **속성**일 뿐. 모든 작업기록·자돈·KPI·이력은 내부키로 연결.
- **이름은 바뀔 수 있고 재사용된다** — 도태된 모돈의 번호를 새 모돈에 다시 붙이는 일이 흔함. 이름으로 연결하면 옛 모돈 데이터가 새 모돈에 붙어 꼬임.
- 표시번호 유니크 제약은 **"활성(USE_YN='Y') 모돈 내에서만"** 걸 것. 과거(삭제·도태) 모돈까지 포함해 유니크 걸면 재사용 불가.

### 1-1. 산차(parity)가 실질 복합키
같은 모돈이 여러 산차를 돈다. 분만·이유·자돈 기록은 **`(모돈키 + 산차)`** 가 실질 키.
- PigPlan: `SANCHA` 컬럼. 분만 시 산차+1.
- PigOS: 분만/이유/포유/자돈 레코드는 `(sow_internal_id, parity)` 로 묶을 것. 산차 누락/중복 = 두수 꼬임 직결.

## 2. Validation — 입력단 도메인 불변식 (가장 중요)

KR 룰셋에서 검증된 불변식. **입력 시점에 막아야** 하류 KPI·두수가 안 꼬인다.

### 2-1. 두수 보존식 (head-count conservation)
- `총산 = 실산 + 사산 + 미라` (분만)
- `실산 ≤ 총산` (항상 — KR FARM_FILTER Q5 "위반 시 입력오류")
- `이유두수 ≤ 포유개시두수` (= 실산 + 양자입 − 양자출)
- `포유중폐사 = 포유개시두수 − 이유두수` (≥ 0)
- **부분합 ≤ 전체, 음수 두수 금지** — 모든 두수 필드 공통.

### 2-2. 기간/생리 범위 (KR VALID_RANGES)
| 항목 | 정상 | 무효(거부) |
|---|---|---|
| 임신기간 | 110~120일 (표준 114) | <100 or >125 |
| 포유기간 | 14~50일 (KR 21~25, EU 28+) | <7 or >60 |
| LSY | 1.5~2.6 (생물 상한 2.66) | >2.8 |

→ **국가별로 다른 정상범위는 `default_metric_values` scope로** (포유기간 KR vs EU). 코드 하드코딩 금지.

### 2-3. 날짜 순서 (이벤트 시퀀스)
- `교배일 < 분만일` (분만 ≈ 교배 + 114일)
- `분만일 < 이유일` (이유 = 분만 + 포유기간)
- `전입일 ≤ 첫 교배일`
- 미래일자 입력 거부, 작업일 > 등록일 경고(입력지연).

### 2-4. 극단값 가드 (KR DATA_QUALITY_GUARD)
- `PSY > 45`, `NPD > 200` = 입력오류로 간주 → KPI 산출에서 제외.
- 분류(등급) 산출 시 KPI가 무효범위면 해당 룰 skip (잘못된 경보 방지).

### 2-5. 산차 연속성
- 신규 분만 산차 = 직전 산차 + 1 (건너뜀/역행 경고).
- 입식산차 + 분만횟수 = 현재 실제산차 (도폐사 손실 산정 기준).

## 3. 두수 정합성 — 흐름 추적

자돈은 **단계별로 줄어드는 흐름**. 각 단계 두수가 앞 단계를 못 넘는다.
```
총산 ──(−사산 −미라)──▶ 실산 ──(−포유중폐사 ±양자)──▶ 이유두수 ──▶ 이유후 ...
```

**모돈 재고(상시모돈) 분류** — PigOS `inventory.zero` 룰이 이미 사용하는 상태값:
`GILT(후보) + OPEN(공태) + PREGNANT(임신) + LACTATING(포유) + ACCIDENT(사고)` = 상시모돈.
- 한 모돈은 **한 시점에 한 상태만** (상태 중복 = 꼬임).
- 상태 전이는 이벤트로만: 교배→임신, 분만→포유, 이유→공태, 사고→공태/도폐.

**입출 구분 (손실 계산 정합성 — KR LOSS_DIAGNOSIS):**
- **자산이동** (손실 아님): 전출, 판매
- **손실**: 도태, 폐사
- 합산 시 이 둘을 섞으면 손실액·두수가 왜곡됨.

## 4. 삭제·수정 — 이력 보존 & cascade 정합성

이번 복구건의 핵심 교훈.

- **소프트삭제만** (`USE_YN='N'` 류 플래그). 물리삭제 금지 → 복구 가능 + 감사추적.
- **모돈 삭제 = 연관 전체 cascade 소프트삭제를 한 트랜잭션으로.**
  - PigPlan 사례: 모돈 1건 삭제 시 `TB_MODON`(마스터) + `TB_MODON_WK`(작업요약) + `TB_GYOBAE/TB_BUNMAN/TB_EU`(교배·분만·이유 상세) + `TB_MODON_JADON_TRANS`(산차이동)가 **모두 USE_YN='N'** 으로 바뀜.
  - 일부만 죽으면 "마스터는 살았는데 분만상세는 죽은" 부분삭제 = 꼬임. **반드시 트랜잭션으로 원자적 처리.**
  - 복구도 같은 집합을 한 번에 flip.
- **타임존**: 시각은 **UTC 저장**, 표시 시 농장 로컬TZ 변환 (PigPlan `LOG_UPT_DT`=UTC라 16:08 KST가 07:08로 보임 — 멀티국가 PigOS는 이 변환 필수).
- 수정은 덮어쓰기 대신 **이력/버전** 권장 (누가·언제·뭘 바꿨나 추적 → 실수 복구 쉬움).

## 5. KPI/기간 산출 시 꼬임 방지 (KR 룰 근거)

- **PERIOD 성격 혼동 금지** (PERIOD_DISTINCTION): `W`(주실적)·`WY`(연환산)·`M`(월합산)·`MY`(월연환산)는 성격이 달라 섞어 비교 금지.
- **off-week 0두는 정상** (AIAO 배치농가): 비작업 주의 0건을 폐사/이상으로 처리 금지. 폐사율 분모가 작을 때 비율 폭등 주의(분모 가드).
- **평균은 0 제외** (활동 0주 제외하고 평균).
- KPI는 **무효범위 가드 통과한 데이터만** 으로 산출 (§2-4).

## 6. 멀티테넌트 격리 (PigOS 신규 관점 — PigPlan엔 없던 강화점)

- 모돈 내부키는 **농장 내 유일**(글로벌 유일 아님). PigPlan `PIG_NO`는 FARM_NO 내 시퀀스.
- **모든 모돈 쿼리에 `farm_id` 항상 포함.** `(farm_id, sow_internal_id)` 복합으로 격리 — farm_id 누락 시 타 농장 모돈과 섞일 위험.
- 표시번호 유니크도 `farm_id` 스코프 내에서만.
- KPI·벤치마크 임계값도 scope(국가/지역/농장)별 (`default_metric_values`) — §2-2 참조.

## 체크리스트 (PigOS 구현 시)
- [ ] 모돈 식별은 내부키, 표시번호로 조인/FK 안 함
- [ ] 표시번호 유니크 = 활성 모돈 + farm 스코프 한정 (재사용 허용)
- [ ] `(sow, parity)` 로 분만/이유/자돈 묶음

- [ ] 삭제 = 소프트삭제 + 연관 cascade 원자적 트랜잭션
- [ ] 시각 UTC 저장 / 농장TZ 표시
- [ ] 모든 쿼리 farm_id 스코프
- [ ] 국가별 정상범위·임계값은 scope 데이터로 (하드코딩 금지)

## 7. PigOS 현황 대비 — 이미 된 것 / 검증할 것 / 갭 (2026-06 코드 확인)

PigOS는 이미 상당히 성숙. 아래는 실제 코드 기준 분류. **"처음부터 만들기"가 아니라 "검증 + 갭 보강".**

### ✅ 이미 구현됨 (유지·검증만)
- **모돈 키/이름 분리**: `sows.id`(UUID PK) + `ear_tag`(표시번호), `UniqueConstraint(farm_id, ear_tag)`.
- **이벤트 분리 저장**: `matings`·`pregnancy_checks`·`farrowings`·`weanings`·`reproductive_events`·`piglet_events` 별도 테이블. `created_at` timezone-aware(UTC).
- **산차/사이클**: `sows.parity`(default 0=GILT) + `breeding_cycles`(산차별, **"모돈당 활성사이클 1개" 부분유니크 인덱스**로 상태중복 차단).
- **상태머신**: `sows.status`(GILT default), `exit_date`(소프트 퇴출).
- **두수 보존식**: `FarrowingCreate.total_born = born_alive + stillborn + mummified` 자동계산, 전 필드 `ge=0`(음수 차단).
- **오프라인 멱등성**: client 생성 UUID → server idempotency, 재전송=merge(에러 아님), `sync_service` **conflict 로그 테이블**.
- **이벤트 dedup**: 동일 `farrowing_id` 이유 1회 제한.
- **멀티테넌트**: 전 테이블 `farm_id` 스코프 + 인덱스.

### ⚠️ 검증 필요 (있는지 확실치 않음 — PigOS가 코드로 확인)
1. **ear_tag 재사용**: `UniqueConstraint(farm_id, ear_tag)`가 **전체 유니크**라, 퇴출(exit_date)된 모돈의 번호를 **새 모돈에 재사용 못 할 수** 있음. 현장은 도태 후 같은 번호 재사용이 흔함 → 부분유니크(`WHERE exit_date IS NULL`)로 바꿀지 검토.
2. **이벤트 간 불변식**: 두수 보존(분만)은 됨. 그러나 **교배일<분만일<이유일 날짜순서**, **이유두수 ≤ 포유개시두수(실산±양자)**, **산차 연속성(분만 시 +1, 역행/건너뜀 차단)** 이 enforce 되는지 확인.
3. **기간/극단값 범위가드**: 임신기간 110~120·포유 14~50·LSY≤2.66·PSY≤45·NPD≤200 입력거부/경고가 있는지. 국가별 범위는 `default_metric_values` scope로.
4. **양자(cross-fostering)**: 포유 중 자돈 이동 시 두 모돈 산차 두수 보존 처리되는지 (두수 꼬임 최대 지점).

### 🆕 갭 (신규 판단)
5. **단위·로캘 정규화**: 다국가 — kg/lb·날짜형식·ear-notation·품종/질병코드. **저장은 정규형(kg·UTC·ISO·WOAH 질병코드), 표시만 변환.** 입력도 즉시 정규화.
6. **정정(correction) 의미론**: 과거 이벤트 수정 시 → 영향 산차/KPI **재계산 트리거** + as-of 재현(이벤트 리플레이). 권한은 어드민 role 게이트(`handoff/pigplan-rules` 핸드오프와 연결).
7. **삭제 cascade 원자성**: PigPlan식 모돈 삭제 시 연관 이벤트 전부 한 트랜잭션 처리(부분삭제 금지). PigOS는 exit_date 소프트퇴출이라 다르지만, **하드삭제 경로가 있다면** 동일 원칙 적용.

## 8. 무결성 코어 — 절대 안 꼬이게 (산차별 · 이벤트별) ⭐핵심

"꼬이면 망한다"의 방어선. 아래 4개를 **명시적 구조로** 두면 데이터 누수·꼬임이 구조적으로 불가능해진다. 산발적 if 검증이 아니라 **불변식을 시스템이 강제**.

### 8-1. 모돈 생애 상태머신 (불법 전이 = 거부)
한 모돈은 **항상 정확히 한 상태**. 상태 전이는 **이벤트로만**. 불법 전이는 입력 자체를 거부.

| 이벤트 | 허용 from-state | → to-state | 부수효과 |
|---|---|---|---|
| entry(전입/후보등록) | (신규) | GILT / OPEN | parity=0 |
| mating(교배) | GILT, OPEN | BRED | 활성 cycle 시작 |
| preg_check(+) | BRED | PREGNANT | — |
| preg_check(−)/return(재발) | BRED | OPEN | cycle 실패마감 |
| abortion/accident(사고) | PREGNANT | OPEN(or ACCIDENT) | cycle 실패마감 |
| farrowing(분만) | PREGNANT | LACTATING | **parity += 1**, 산차원장 개시 |
| weaning(이유) | LACTATING | OPEN | 산차원장 마감, WEI 시작 |
| cull/death/sale/transfer(도폐/판매/전출) | any | EXIT | exit_date 설정, 활성 cycle 종료 |

- **불변식**: 활성 cycle ≤ 1 (PigOS 부분유니크 이미 있음). farrowing while ≠PREGNANT, weaning while ≠LACTATING = **reject**.
- 상태는 이벤트 로그에서 **파생**(derive). 저장된 status는 캐시일 뿐 — §8-4가 검증.

### 8-2. 산차별 자돈 원장 (double-entry, 항상 balance)
**산차 꼬임의 99%는 자돈 두수.** 각 `(sow_id, parity)` 마다 원장을 두고, 자돈에 영향 주는 모든 이벤트를 **부호있는 원장기입**으로. 원장은 **항상 0으로 닫혀야** 한다.

```
[유입]  born_alive + fostered_in
  =
[유출]  weaned + died_preweaning + fostered_out + still_nursing(미마감)
```
- **분만**: born_alive(+), stillborn/mummified는 별도(원장 밖, total_born에만).
- **양자(cross-fostering)**: `(sowA,pA) fostered_out = (sowB,pB) fostered_in` — **반드시 짝지은 2개 기입(double-entry).** 한쪽만 기록하면 두수 증발/창조 → 꼬임. 전송은 원자적 트랜잭션.
- **폐사/이유**: died_preweaning(−), weaned(−).
- **이유 마감 시 still_nursing → 0**, 모든 자돈 귀속 완료. 안 맞으면 reject.
- **불변식**: 어느 시점이든 `유입 − 유출 = still_nursing ≥ 0`. 음수·초과 = reject.

### 8-3. 이벤트 계약 (per-event contract) — 입력마다 강제
모든 이벤트 핸들러는 동일 계약을 따른다:
1. **precondition**: 모돈 상태·산차가 이 이벤트를 받을 수 있나 (§8-1). 아니면 reject.
2. **idempotency**: client UUID로 중복 차단 (재전송=동일결과).
3. **occurred_at vs created_at 분리**: 상태/원장 파생은 **occurred_at(논리 발생시각)** 순서로. created_at(동기화 도착시각)으로 정렬 금지 → 오프라인 늦게 도착해도 순서 보존.
4. **invariant 검증**: 날짜순서·두수보존·범위가드 (§2) 전부 통과해야 commit.
5. **atomic**: 상태전이 + 원장기입 + 파생갱신을 **한 트랜잭션**. 부분반영 금지.
6. **append-only 지향**: 수정/삭제는 정정·취소 이벤트로 (덮어쓰기 대신). 이력·복구·as-of 공짜.

### 8-4. 정기 정합성 감사 (drift detection) — 꼬임 조기탐지
저장된 집계(parity·status·재고·KPI)를 **이벤트 로그에서 재파생해 대조**하는 스케줄 잡. 불일치=알림.
```
재파생 parity/status/원장잔량  ==  저장값  ?  → 다르면 즉시 flag
```
- **왜**: PigPlan은 "180 KPI" 환각·부분삭제처럼 **꼬임을 몇 달 뒤 발견**. PigOS는 매일/매시 자동 대조로 **당일 탐지**.
- 농가별 원장 미마감(still_nursing>0인데 이유 끝), 상태-이벤트 불일치, 두수 음수, 고아 이벤트(부모 모돈 EXIT인데 후속 이벤트) 등을 룰로.
- 어드민(`handoff/pigplan-rules` 핸드오프)에 **정합성 대시보드**로 노출.

### 핵심 한 줄
**상태는 이벤트에서 파생(8-1) · 두수는 산차원장으로 보존(8-2) · 입력은 계약으로 강제(8-3) · 드리프트는 매일 감사(8-4).** 이 4겹이면 "모돈별·산차별·이벤트별로 안 꼬인다"가 구조적 보장이 된다.

## 9. 엣지케이스 전수 카탈로그 — 모든 case를 연다 ⭐⭐

happy-path만 짜면 현장 데이터 한 번 꼬이고 농가 이탈. **아래 모든 케이스에 정의된 동작 + 테스트가 있어야 한다.** 각 case: 상황 → 위험 → 처리. (PigOS는 이 목록을 출발점으로, 빠진 케이스를 더 찾아 채울 것.)

### 9-A. 교배(mating)
| case | 위험 | 처리 |
|---|---|---|
| 동일 발정에 복수 교배(AI 2~3일 연속 + 본교) | 교배 N건 → 산차 N개로 오인 | 1 발정window = 1 cycle. 같은 cycle에 교배 여러건 허용, 산차 1개 |
| 재발(return) 후 재교배 | 새 산차로 오인 / 이전 cycle 미마감 | 이전 cycle 실패마감 후 같은 parity로 재교배(분만 전엔 parity 유지) |
| 후보돈(GILT) 첫 교배 vs 경산돈 | parity 기준 다름 | GILT는 P0→첫분만 시 P1. 상태머신으로 구분 |
| 임신확인 후 교배 입력 | 상태 역행 | precondition 위반 → reject 또는 정정유도 |
| 웅돈/정액 혼합·미상 | 혈통 추적 불가 | 허용하되 sire 미상 플래그, 혈통KPI 제외 |

### 9-B. 임신감정(pregnancy check)
| case | 위험 | 처리 |
|---|---|---|
| 양성 후 음성(흡수/유산) | 임신두수 과대 | 음성=cycle 실패마감→OPEN. 임신재고 즉시 감소 |
| 감정 누락 → 바로 분만 | 상태 BRED인데 분만 | 분만 이벤트가 PREGNANT로 보정(역추론) + 경고 |
| 복수 감정(28일·42일) | 중복 카운트 | 동일 cycle 다회 감정 허용, 최신 결과가 상태 결정 |

### 9-C. 분만(farrowing)
| case | 위험 | 처리 |
|---|---|---|
| 교배기록 없는 분만 | 고아 분만·parity 불명 | 허용하되 cycle 역생성 + parity 추정/입력요구, 데이터갭 플래그 |
| 실산 0(전 사산/미라) | 원장 개시 0 | total_born>0, born_alive=0 정상처리. 포유원장 0 마감 |
| 임신기간 범위밖(예 95일·130일) | 입력오류 가능 | §2-2 범위가드: 무효는 reject, 경계는 warning |
| 조산/유산 vs 분만 경계 | 분류 모호 | 일령·생존 기준으로 abortion/farrowing 구분 룰 |
| 분만 중복입력 | 산차 2개 생성 | 동일 cycle 1 farrowing(dedup), 재전송 merge |
| 시스템상 OPEN인데 분만 | 상태 불일치 | 감정누락 보정(9-B) 또는 reject+정정 |

### 9-D. 양자(cross-fostering) — 두수 꼬임 최대 ⚠️
| case | 위험 | 처리 |
|---|---|---|
| 분만 당일 양자 | 출생귀속 모호 | 출생은 원산차에 귀속, 양자는 별도 transfer 기입 |
| 1마리를 여러 모돈에 분산 | 합계 불일치 | 각 transfer를 짝지은 double-entry, 합=원두수 |
| 다른 산차/유모돈(nurse sow)에 위탁 | 위탁모 산차 두수 오염 | nurse_sow_flag, 위탁분은 위탁모 "포유중"에 +이되 그 산차 출생엔 미산입 |
| 양자 연쇄(A→B→C) | 추적 끊김 | 각 단계 독립 double-entry, 원장 체인 보존 |
| 위탁 자돈을 위탁모가 이유 | 이유두수 귀속 분쟁 | 이유는 "현재 포유중인 모돈" 기준, 출생은 원산차 — 분리 집계 |
| 양자 취소/되돌림 | 한쪽만 취소 | 양쪽 transfer 동시 취소(원자적) |

### 9-E. 이유(weaning)
| case | 위험 | 처리 |
|---|---|---|
| 부분이유(일부만) | 원장 조기마감 | 부분 weaned 기입, still_nursing 잔존. 전량 이유 시 마감 |
| 분할이유(여러날) | 이유두수 합산오류 | 다회 weaning 허용, 합=포유두수 이하 |
| 이유두수 > 포유두수 | 두수 창조 | reject (원장 음수) |
| 이유 0(전폐사) | — | 정상, 원장 폐사로 마감 |
| 이유 중복 | 재고 오류 | 동일 cycle dedup |

### 9-F. 폐사·도태·전출(removal)
| case | 위험 | 처리 |
|---|---|---|
| 포유 중 모돈 폐사 | 자돈 고아 | 자돈 강제 양자 or 폐사 처리 요구, 미처리 시 원장 미마감 flag |
| 임신 중 모돈 폐사/도태 | 임신재고 안 줄음 | cycle 강제마감, 임신재고 감소 |
| 자돈 폐사: 포유 vs 이유후 | 폐사율 산식 다름 | 일령/마감여부로 pre/post-wean 구분 |
| 전출/판매 vs 도태/폐사 | 손실액 왜곡 | 자산이동(전출·판매) vs 손실(도태·폐사) 분리(§3) |
| 도태 후 같은 ear_tag 재사용 | 옛 모돈 이력 혼입 | §7-1 부분유니크, 신규 UUID로 완전분리 |

### 9-G. 전입·재입(entry)
| case | 위험 | 처리 |
|---|---|---|
| 이미 임신상태로 전입 | parity·임신일 불명 | entry_type=임신전입, parity·교배일 입력/추정 |
| 판매한 모돈 재입 | 키 중복/이력단절 | 신규 UUID + 이전이력 링크(옵션), ear_tag 재사용 허용 |
| 농장간 이동(같은 회사) | 이력 소유 모호 | 전출농장 EXIT + 전입농장 신규, source_farm 링크 |

### 9-H. 산차(parity)
| case | 위험 | 처리 |
|---|---|---|
| 분만 없는 사고/재발 | parity 오증가 | parity는 **분만 시에만** +1 |
| 입력 parity 오류 정정 | 하류 산차 전부 틀어짐 | 정정이벤트 + 영향 cycle 재계산(§8-4) |
| 전산 이전 과거산차 | P0인데 분만이력 | 초기 parity 보정 입력 허용 |

### 9-I. 동기화·순서(offline/sync)
| case | 위험 | 처리 |
|---|---|---|
| 이벤트 역순 도착(이유가 분만보다 먼저) | 상태 꼬임 | occurred_at 순 파생(§8-3), 도착순 무시 |
| 동일 이벤트 2기기 | 중복 | client UUID 멱등 merge |
| 삭제된 모돈에 후속 이벤트 도착 | 고아 이벤트 | reject+conflict 큐, 사람 해소 |
| 미래일자/백데이트 | 비현실 데이터 | 미래 reject, 백데이트는 마감산차 재계산 트리거 |
| 두 사용자 같은 모돈 오프라인 수정 | 충돌 | 둘 다 이벤트 보존+conflict 로그, last-write 덮어쓰기 금지 |

### 9-J. 정정·삭제(correction)
| case | 위험 | 처리 |
|---|---|---|
| 분만 삭제했는데 이유 존재 | 고아 이유 | cascade 정합 검사, 종속이벤트 있으면 차단/연쇄정정 |
| 마감산차의 born_alive 수정 | KPI 소급변동 | 정정이벤트 + as-of 재현 + 영향KPI 재계산 |
| 양자 되돌림 | 한쪽만 | 양쪽 동시 취소(9-D) |
| 모돈 통째 삭제(이번 PigPlan 사례) | 부분삭제·복구난 | 소프트(exit), 하드면 연관 전부 원자트랜잭션 |

### 핵심
**위 10개 카테고리 × 모든 row가 각각 정의된 동작 + 테스트를 가져야 한다.** 빠진 case는 PigOS가 추가 발굴. "이 case는 안 일어남" 가정 금지 — 현장은 다 일어난다.
